# אימוני כושר (tavor-gym)

אפליקציית ווב אישית לניהול אימוני כוח. מנחה איזה תרגיל לעשות עכשיו, מציגה דגשי ביצוע וסרטון הדגמה, מתעדת כל סט, מפעילה טיימר מנוחה, ומראה התקדמות לאורך זמן.

**משתמש יחיד · עברית RTL · אופליין מלא · בלי שרת, בלי חשבון, בלי ענן.**
כל הנתונים נשארים במכשיר, ב-IndexedDB.

---

## הרצה

```bash
npm install
npm run dev          # פיתוח
npm run build        # בנייה לייצור
npm run preview      # בדיקת ה-build כולל Service Worker
npm test             # בדיקות יחידה
npm run typecheck    # בדיקת טיפוסים
```

סקריפטים נוספים:

```bash
npm run gen:icons      # מייצר מחדש את אייקוני ה-PWA
npm run import:videos  # דוחס מחדש את הסרטונים מתיקיית "תוכנית אימונים"
npm run check:size     # שומר על משקל ההתקנה (רץ גם בפריסה)
npm run gen:hashes     # מחשב מחדש טביעות אצבע לזיהוי סרטונים כפולים
```

## התקנה לאייפון

1. לפתוח את הכתובת בספארי (לא בכרום)
2. שיתוף ← **הוסף למסך הבית**
3. לפתוח מהאייקון במסך הבית — לא מהדפדפן

> **חשוב:** ל-PWA מותקן ב-iOS יש אחסון **נפרד** מלשונית ספארי. נתונים שנוצרו בלשונית לא יופיעו באפליקציה המותקנת. כל השימוש האמיתי צריך לקרות מהאייקון.

אחרי ההתקנה: הגדרות ← סרטונים ← **התקן סרטונים למכשיר**. בלי זה הסרטונים דורשים רשת.

### שלושה כללים שחוזרים בכל הקוד

1. **משקל מוצג בדיוק כמו שרשום על המכונה.** ההכפלה של `perSide` קורית רק בחישוב נפח, בפונקציה אחת (`domain/volume.ts`). בכל מקום שמופיע משקל של תרגיל `perSide` מופיעה גם התווית "כל צד".
2. **סטי חימום נשמרים ומוצגים, אבל לא נספרים.** לא בנפח, לא בשיאים, ולא בהמלצות המשקל.
3. **`domain/` הוא פונקציות טהורות.** נכנס מידע פשוט, יוצא מידע פשוט. זה מה שמאפשר לכסות את כל האינטליגנציה של האפליקציה בבדיקות יחידה.

### מערכת העיצוב

`styles/theme.css` מחזיק את כל הצבעים כמשתני CSS, ולסולם ה-`bone` יש כלל אחד
שאסור לשבור: **`bone-600` אינו צבע טקסט.** הוא עומד על 3.0–3.5:1 מול הרקעים,
מה שמספיק לאייקון או לגבול ולא למילים. טקסט משני הוא `bone-500` (4.5–5.3:1)
וטקסט ראשי הוא `bone-50`.

הכלל הזה נכתב אחרי מדידה: קודם `.meta` ישב על 3.9:1 מול כרטיס וטקסט ב-`bone-600`
על 2.4:1 — מתחת לסף של WCAG AA, על מסך שולחני. את המספרים האלה קוראים בחדר
כושר מואר, עם המסך בזווית, ולכן זה בדיוק המקום שבו הפער נפתח.

### למה שני מסדי נתונים

הסרטונים יושבים ב-`tavor-gym-media` נפרד. כתיבה של Blob של מגה-בייטים לא מעירה שום `liveQuery` על טבלאות הנתונים, ייצוא הנתונים לא נאלץ לגרור וידאו דרך הזיכרון, ומיגרציית סכמה לא נוגעת במדיה.

### התאוששות מקריסה

מצב האימון הפעיל נכתב לשורה אחת ב-`activeWorkout` אחרי **כל** פעולה. הסטים עצמם נכתבים ל-`setLogs` מיד כשהם נסגרים — הטבלה היא האמת העמידה, וה-store הוא רק מראה בזיכרון. אם האפליקציה נהרגת באמצע סט, הפתיחה הבאה מציעה להמשיך.

אסור להאזין לטבלת `activeWorkout` עם `useLiveQuery` — היא נכתבת אחרי כל נגיעה.

## ספריית התרגילים

מסך הבית ← **כל התרגילים** (`/exercises`): כל הקטלוג, מחולק לפי קבוצת שריר
**מהגדול לקטן** (`MUSCLE_GROUP_BY_SIZE`), עם המשקל האחרון שהורמת בכל תרגיל.
כל שורה: השם בעברית, מתחתיו **השם באנגלית** בקטן — זה מה שכתוב על המדבקה של
המכונה ומה שמחפשים בו סרטון — ואז המיקוד והציוד.

שני זוגות תרגילים נושאים בכוונה את אותו שם עברי (שתי חתירות במכונה, ושתי
לחיצות חזה במכונה). הם לא מאוחדים — היסטוריה נפרדת, סרטון נפרד — ולכן כל
רשימה שמציגה שניים כאלה זה לצד זה מוסיפה את המשקל כמבדיל
(`domain/naming.ts`).

לחיצה על תרגיל פותחת את מסך התרגיל (`/exercise/:id`): כמה אני עושה בזה,
הדגמות, דגשי ביצוע, היעד, שיאים, המלצה להיום, גרפי מגמה, וההיסטוריה המלאה.

מסך הבית ← **עריכת האימונים** (`/settings/plans`): הוספה, הסרה, שינוי סדר,
ועריכת סטים/חזרות/מנוחה לכל תרגיל בכל תוכנית ובלוק — כולל האימונים השמורים,
שהם היחידים שאפשר גם לשנות להם שם ולמחוק.

מסך הבית ← **בניית אימון** (`/builder`): אותם תרגילים, מסודרים לפי מה שהוזנח
במקום לפי הקטלוג. ראה [בניית אימון](#בניית-אימון).

## ברירות מחדל אחידות

כל תרגיל נפתח על **2 סטים** ו-**2 דקות מנוחה**, ושדה החזרות מוצע על **6** כשאין
עדיין היסטוריה (`DEFAULT_TARGET_SETS`, `DEFAULT_REST_SECONDS`, `DEFAULT_REPS`
ב-`db/seed.ts`). האחידות מכוונת: להיכנס לכל תרגיל עם אותה ציפייה ולשנות אותה
במקום, במקום לזכור מספר משלו לכל תרגיל.

שלוש רמות שינוי, מהקבוע לזמני: הגדרות ← עורך התוכניות ← **הכרטיס באמצע אימון**.
השינוי בכרטיס חי בתור בלבד ולא נכתב לתוכנית — "היום אני עושה עוד סט" ו"התוכנית
שלי היא שלושה סטים" הן שתי כוונות שונות.

## תרגיל שנמדד בזמן

`Exercise.metric` הוא `'reps'` (ברירת מחדל) או `'seconds'`. פלאנק הוא `'seconds'`
עם יעד של 1:15. הערך נשמר באותו שדה `SetLog.reps` ולא בשדה חדש — מבחינת הנפח,
השיאים וההמלצות זה אותו מספר, ורק התצוגה שואלת מה היחידה שלו. פיצול לשדה נפרד
היה מכפיל כל פונקציה ב-`domain/` בלי להרוויח דבר.

תרגיל זמן נמדד עם **סטופר מסך-מלא** ("מדוד עם סטופר" בכרטיס): הספירה עולה,
ביעד יש צליל והבזק, והיא **ממשיכה גם אחרי היעד** — מי שהחזיק 1:30 מתעד 1:30.
"עצור" מציג את התוצאה עם אישור לפני הרישום, כי יד רועדת אחרי פלאנק לוחצת גם
בטעות. כמו טיימר המנוחה, הזמן מחושב מחותמת התחלה ולא מצבירת טיקים
(`useStopwatch`) — iOS מקפיא טיימרים כשהמסך כבה.

## תיעוד מדויק — דילוג, סיום מוקדם ומתגי היום

כל סט נכתב ל-`setLogs` ברגע הלחיצה, ולכן "כמה סטים באמת עשיתי" תמיד מדויק.
מה שנוסף מעל זה:

- **"סיים תרגיל"** סוגר את התרגיל אחרי כמה סטים שנעשו בפועל — סט אחד מתוך
  שלושה מתועד כסט אחד. אם מתג הדירוג דלוק ויש סטים בלי דירוג, שאלון "איך
  היה" נפתח קודם והסגירה מחכה לו.
- **"דלג היום"** (בכרטיס הפעיל ובכל שורה בתור) מסמן `status: 'skipped'`:
  התרגיל לא נספר כבוצע, לא חוסם את סיום האימון, ומופיע בגיליון הסיום
  כהחלטה ("דילגת עליהם") ולא כאזהרה. נגיעה בו בתור מחזירה אותו. סגירה של
  תרגיל בלי אף סט היא דילוג ולא השלמה — ✓ על תרגיל ריק היה עוקף בשקט את
  האזהרה של "סיים אימון".
- **שלושה דילוגים רצופים** על אותו תרגיל פותחים הצעה להוציא אותו מהתוכנית.
  הספירה היא על דילוג *מוצהר* בלבד (`Session.deliberatelySkippedIds`) ולא על
  "לא הגעתי" — אימון שנגמר באמצע משאיר חצי תוכנית בלי סטים, וספירה שלו הייתה
  מסמנת שבעה תרגילים כמיותרים אחרי שלושה ערבים עמוסים. "המתקן תפוס" מוחרג גם
  הוא. הכפתור הראשי בהצעה הוא *להשאיר*, וההוצאה נוגעת לתוכניות ולבלוקים בלבד.
- **שני מתגים בראש מסך האימון** — "טיימר מנוחה" ו"שאלון קושי" — כי אלה
  החלטות של יום, לא של התקנה: מי שמתעד מנוחה ב-Apple Watch מכבה את הטיימר
  (אפשר גם מתוך מסך המנוחה עצמו), ומי שאין לו אנרגיה לתעד קושי מכבה את
  השאלון והוא לא מופיע בכלל. שניהם נשמרים ב-`AppSettings` וזמינים גם בהגדרות.

## הקצב — מה שנאסף גם כשהטיימר כבוי

לכל סט יש חותמת סיום, ולכן ההפרש בין שני סטים עוקבים של אותו תרגיל ידוע בדיוק
בלי שום תיעוד נוסף. מסך הסיכום ופירוט האימון מציגים את **החציון** שלו.

**"זמן בין סטים" ולא "מנוחה", וזה לא ניסוח זהיר אלא דיוק:** `completedAt` הוא
סוף הסט, ולכן ההפרש כולל את המנוחה *ועוד* משך הסט הבא — ובתרגיל חזרות אין לנו
את משך הסט כדי להפריד. קריאה לזה "מנוחה" הייתה מנפחת כל מספר בעשרים-שלושים
שניות בשקט.

חציון ולא ממוצע, והפרש מעל 15 דקות נספר כהפסקה ומסונן: סט אחד שהתעכב בגלל
מתקן תפוס לא אמור להזיז את המספר שמתאר את כל האימון. `domain/pacing.ts`.

## שתי תוכניות אימון

באפליקציה שתי שיטות, ובכל רגע פעילה אחת מהן. ההחלפה היא בלחיצה בהגדרות ←
תוכניות ובלוקים. תוכנית כבויה נשארת במסד עם כל ההיסטוריה שלה — היא רק לא
מוצעת במסך הבית, כדי ששתי שיטות לא יתערבבו ב"מה מתאמנים היום".

| | פול באדי (ברירת מחדל) | פיצול A/B/C |
|---|---|---|
| אימונים | 2 מתחלפים | 3 |
| תרגילים לאימון | 8 | 5–9 + בלוקים |
| לכל שריר | 1–2 לפי גודל | 2–4 |
| סטים | 2 | 2 |
| טווח חזרות | 10–15 | 8–12 |
| משקל התחלה | ‎~60% מהמשקל הקודם | המשקל המלא |
| בלוקים נלווים | לא — הגוף כולו מכוסה | כן |

אין תרגיל חימום קבוע בראש התוכנית. חימום נקשר ל**שריר** ולא לאימון — שכיבות
סמיכה מחממות חזה ולא עושות כלום לרגליים — ולכן ההצעה מגיעה מ-`domain/warmup.ts`
ברגע שנפתחת קבוצת שריר חדשה, עם משקל מופחת של אותו תרגיל שעומדים לעשות.

**פול באדי** נועד לחזרה הדרגתית אחרי הפסקה. משקל ההתחלה נשמר ברמת התוכנית
(`PlanItem.startWeightKg`) ולא ברמת הקטלוג, ולכן אותו תרגיל מתחיל קל בתוכנית
החזרה וכבד בפיצול — בלי לגעת בשיאים ובהיסטוריה. ברגע שיש היסטוריה, מנוע
ההמלצות משתלט ומשקל ההתחלה כבר לא רלוונטי.

## בניית אימון

התוכניות עונות על "מה התוכנית אומרת היום". מסך בניית האימון עונה על השאלה
ההפוכה — **על מה לא עבדתי** — ולכן הוא ממוין מהשריר המוזנח ביותר ולא בסדר קבוע,
וכל תשע הקבוצות מופיעות גם באפס. קבוצה שנעלמת מהמסך היא בדיוק זו שממשיכים לשכוח.

הזרימה: מסך הבית ← רשימת השרירים עם ספירת החלון ← תרגילי השריר ← סל ← יעד.

**החלון** הוא ימים קלנדריים ולא 24 שעות: ארבעה ימים הם היום ושלושת שלפניו
(`daysSince(x, now) <= windowDays - 1`), ניתן לשינוי בהגדרות. שלושת כללי הספירה
זהים למסך הבית ולכן המספרים לא סותרים זה את זה: רק אימון שנסגר ויש בו סט עבודה,
רק סטי עבודה, וגיל נמדד לפי `startedAt` של האימון כדי שאימון שחצה חצות לא יתפצל.

**עבודה עקיפה** נספרת בנפרד. `Exercise.secondaryMuscles` מתייג מה שהתרגיל מעמיס
בעקיפין (חתירה → יד קדמית), והמסך מציג "+N עקיף" לצד המספר הישיר ולא בתוכו:
לדעת שהיד קיבלה משהו זה שימושי, אבל זה לא "אימנתי יד קדמית". התיוג יושב במפה
סטטית (`db/muscleTags.ts`) שמכסה את הקטלוג ואת המאגר, וניתן לעריכה בעורך התרגיל.
המספרים האלה מזינים **רק** את מסך הכיסוי — לא את הנפח השבועי (שם הם היו מנפחים
את הסך), לא את החימום ולא את מועמדי ההחלפה.

**הסל** נשמר ב-localStorage ולא ב-state של מסך: הבחירה נמשכת בין שני מסכים,
ו-iOS סוגר PWA שברקע בלי היסוס. ארבעת היעדים הם ארבע כוונות נפרדות — לאימון
שרץ, אימון חדש, שמירה כאימון בשם, או הוספה לתוכנית — והקיר בין "להיום" ל"לתוכנית"
הוא אותו קיר שקיים כבר בכל האפליקציה (שינוי יעד באמצע אימון לא נכתב לתוכנית).

**אימון שמור** הוא שורה בטבלת התוכניות עם `kind: 'custom'`. שתי נקודות שבלעדיהן
הוא שובר את מסך הבית: `getActiveRoutines()` מסנן אותו החוצה (אחרת אימון שמור חדש
היה חוטף את ההצעה היומית — "מעולם לא בוצע" גובר על כל ותק), ו-`activateRoutines`
מדלג עליו (אחרת מתג התוכניות היה מכבה אותו). אצלו `isActive` פירושו "לא נמחק":
המחיקה רכה, כי מחיקת השורה הייתה מייתמת את השם של כל אימון בהיסטוריה שבוצע לפיו.

## מנוע המלצת המשקל

רץ על האימון האחרון של אותו תרגיל, על סטי עבודה בלבד.

הדירוג הוא סולם של חמש דרגות: **קל מאוד · קל · בינוני · קשה · קשה מאוד**
(עד מיגרציה 7 היו שלוש; הערכים הישנים תורגמו לאמצע הסולם, גם במסד וגם
בייבוא גיבוי ישן — ראה `BACKUP_SCHEMA_VERSION`). שאלון הדירוג עצמו הוא מתג
(`askRating`): באימון שאין כוח לתעד — מכבים אותו ממסך האימון והוא לא מופיע.

| מצב | פעולה |
|---|---|
| כל סטי העבודה הגיעו לראש הטווח, והדירוג קל או בינוני | לעלות בקפיצה אחת |
| כנ״ל בדירוג "קל מאוד" (בלי RIR שסותר) | לעלות **בקפיצה כפולה** |
| כנ״ל בדירוג "קל" עם RIR ‎3+ | לעלות **בקפיצה כפולה** — היה קל מדי |
| עברו 3 שבועות מאז האימון האחרון בתרגיל | לרדת מדרגה (‎~90%) |
| עברו 8 שבועות ומעלה | לרדת הרבה (‎~75%) |
| הגיע לראש הטווח אבל דירג קשה או קשה מאוד (או RIR 0) | להישאר |
| לא הגיע לתחתית הטווח | להישאר |
| לא הגיע לתחתית הטווח בשני אימונים ברצף | להוריד 10% |

RIR 0 נחשב כשל וגובר על דירוג "קל" שנלחץ בטעות, וגם ההפך נכון: "קל מאוד" עם
RIR מפורש של 1–2 מקבל קפיצה אחת בלבד — המדד המדויק גובר על הגס. ההמלצה
מוצגת כהצעה עם הסבר בשורה אחת, ולעולם לא מוזנת אוטומטית בלי לחיצה.

**הטווח נמדד רק על סטים במשקל העבודה.** האפליקציה חוגגת ניסיון שיא בקונפטי,
והסינגל הזה נרשם כסט עבודה — בלי הסינון הוא היה מוריד את "הסט הנמוך" מתחת
לטווח והופך המלצת עלייה להקפאה, ופעמיים ברצף להורדת 10% דווקא כשמתחזקים.

**חימום** נגזר מהשריר שנפתח ולא מהאימון: `domain/warmup.ts` מציע סט אחד ברוב
התרגילים, ורמפה של שלושה סטים עולים בתרגיל מורכב כבד (הסף נבחר מול הקטלוג
האמיתי). לתרגילי משקל גוף המנוע נותן יעד קונקרטי מהפעם הקודמת במקום לשתוק.

## המכשולים של iOS ואיך הם מטופלים

| מכשול | הפתרון בקוד |
|---|---|
| ספארי חוסמת אודיו שלא נובע ממחוות משתמש | `AudioContext` נפתח בלחיצה על "התחל אימון" ונשאר חי לכל האימון (`useAudioCue`) |
| מוזיקה ברקע נעצרת כשחוזרים לאפליקציה | `navigator.audioSession.type = 'ambient'` — האפליקציה מתערבבת עם המוזיקה במקום להשתלט עליה. `'playback'` היה מפסיק אותה בכל הערה של ה-`AudioContext` |
| מתג ההשתקה החומרי משתיק WebAudio | הבזק כתום על כל המסך בסיום המנוחה. זו התוצאה של הבחירה ב-`ambient` שלמעלה, וההחלטה מודעת: מוזיקה שממשיכה שווה יותר מצפצוף שעובד גם כשהטלפון מושתק. מכיוון שההבזק הוא ה-cue היחיד שנשאר, יש לו `animation-fill-mode: both` ושכבה סטטית תחת "הפחתת תנועה" — בלעדיהם הוא היה נשאר כתום אטום על כל המסך |
| סרטון שמפסיק להיות mute חוטף את מושב האודיו | `VideoPlayer` אוכף `muted` גם אחרי נגיעה בפקדים. לסרטונים אין בכלל רצועת אודיו, ולכן אין מה להפסיד |
| `navigator.vibrate` לא נתמך באייפון | לא בשימוש בכלל |
| המסך נכבה באמצע אימון | Screen Wake Lock, ובקשה מחדש בכל `visibilitychange` |
| טיימר שסוטה | הכל מחושב מול חותמת זמן סיום, אף פעם לא מצבירת `setInterval` |
| אין ריצה ברקע | אם הדדליין עבר בזמן שהמסך היה כבוי, הצליל מתנגן מיד בחזרה לאפליקציה |
| ספארי עלולה למחוק נתונים | `navigator.storage.persist()`, תצוגת שימוש באחסון, ואזהרה מפורשת אם הבקשה נדחתה |
| `a[download]` לא אמין ב-standalone | ייצוא דרך `navigator.share` עם fallback לעוגן |
| `100vh` משקר | `dvh` + `env(safe-area-inset-*)` בכל מקום |
| זום אוטומטי על פוקוס | כל שדה קלט בפונט ‎16px לפחות |
| זום בצביטה ובלחיצה כפולה | `touch-action: pan-x pan-y`, ביטול אירועי `gesture*` וחסימת לחיצה כפולה — ספארי מתעלמת מ-`user-scalable=no` |
| סימון טקסט ותפריט לחיצה ארוכה | `user-select: none` על הגוף, עם החרגה מפורשת לשדות קלט |
| עדכון SW באמצע סט | `registerType: 'prompt'`, וההודעה מושתקת כל עוד יש אימון פעיל |

**אין התראות Push.** בכוונה.

## הסרטונים

34 סרטוני הדגמה מגיעים מ-`~/projects/תוכנית אימונים (Workout Program)/`, נדחסים ל-720px בצד הארוך בלי אודיו, ונשמרים ב-`public/videos/` יחד עם תמונה ממוזערת לכל אחד. 71MB ← 26MB.

הם **לא** נכנסים ל-precache של ה-Service Worker — 26MB היו הופכים את ההתקנה לשברירית. במקום זה יש כפתור "התקן סרטונים למכשיר" שמוריד אותם ל-IndexedDB, וזה מה שהופך אותם לזמינים אופליין.

להוספת סרטון: לשים קובץ `NN.mp4` בתיקיית התרגיל תחת "תוכנית אימונים" ולהריץ `npm run import:videos`, או לייבא קובץ ישירות מהאפליקציה.

**ניהול הסרטונים** נעשה מתוך הנגן — כפתור המחוונים בכותרת פותח פאנל עם
שלוש פעולות לכל סרטון: **סדר** (חיצים; הראשון ברשימה נפתח ראשון והוא גם
התמונה שעל הכרטיס), **העברה** לתרגיל אחר או ל"מדף" של קבוצת שריר (לסרטון
שמדגים כמה תרגילים; המדף מוצג בראש הקבוצה במסך התרגילים), ו**מחיקה**.
הסדר וההעברות נשמרים ב-`AppSettings` (`videoOrder`, `videoMoves`) מאותה סיבה
כמו `hiddenVideoIds`: המניפסטים מג'ונרטים וה-Blob-ים מתחלפים, וההחלטה חייבת
לשרוד את שניהם ולהיכנס לגיבוי בחינם. מזהה מת (סרטון שהוחלף בייבוא) נסבל בשקט.

**זיהוי כפילויות** יושב בהגדרות ← סרטונים, ומופיע רק כשיש מה להציג. המאגר צמח
מייבוא אוטומטי, ואותו סרטון נכנס אליו יותר מפעם אחת תחת שמות שונים — פעם אחת
כבר נמחקו 33 כאלה ידנית, בהשוואת פריימים.

ההשוואה היא על **טביעת אצבע תפיסתית של התמונה הממוזערת** (dHash 64 סיביות,
`scripts/gen-video-hashes.mjs` → `db/videoHashes.ts`), ולא על גודל הקובץ ומשך
הסרטון. זו לא העדפה אלא מדידה: על 488 הקליפים שבמניפסטים **אין אף זוג** עם אותו
גודל ואותו משך, כי כל עותק עבר קידוד מחדש בפרמטרים אחרים — זוגות שהם באמת אותו
סרטון נבדלים בעד 7 שניות ובעד 58% גודל. השוואת מטא-דאטה הייתה מחזירה אפס
כפילויות אמיתיות ועשרות שגויות. ההשוואה מוצאת 7 זוגות זהים לחלוטין ו-26
מועמדים בסך הכל.

המילה "מועמדים" מכוונת: פריים פתיחה זהה אינו הוכחה, ולכן כל שורה נפתחת בנגן
להשוואה לפני שמוחקים. הטבלה נוצרת בזמן בנייה ולא בדפדפן — 488 פענוחי תמונה בכל
פתיחת מסך הם בזבוז על נתון שלא משתנה בין פריסות.

**מחיקת סרטון** נעשית מהפאנל או מסל האשפה בכותרת, עם אישור לפני. סרטון שנמחק
נעלם מכל מקום באפליקציה: מהנגן, מהתמונה הממוזערת בכרטיס התרגיל, מהמאגר
וממוני ההתקנה. המזהה נשמר ב-`AppSettings.hiddenVideoIds` ולא רק כמחיקת Blob,
כי רוב הסרטונים מצורפים לאפליקציה — בלי זיכרון להחלטה הם היו חוזרים מהרשת
בפתיחה הבאה ומההתקנה הבאה. הרשימה נכנסת לגיבוי הנתונים בחינם, ואפשר לשחזר
הכל בהגדרות ← סרטונים.

שלושה תרגילים (`A04`, `A05`, `B07`) מעולם לא צולמו ומציגים מצב ריק מסודר. שלושה אחרים מוצמדים לסרטון שמראה תרגיל אחר — הם רשומים ב-`db/videoIssues.ts` ומסומנים באזהרה בכל מקום שמנגנים אותם, עד שיוחלף הסרטון.

## פריסה

```bash
npm run deploy
```

הסקריפט מריץ את הבדיקות, בונה, דוחף את `dist/` לענף `gh-pages` ש-Pages מגיש
ממנו, **וממתין עד שהקובץ החדש באמת מוגש מהשרת**. הוא נכשל אם משהו בדרך נשבר —
דחיפה מוצלחת אינה פרסום, ובניית Pages מהענף כבר נתקעה ונכשלה בעבר. אם היא
נכשלת, הרצה חוזרת דוחפת קומיט חדש שמעורר בנייה טרייה.

הוא מסרב לפרוס עץ עבודה מלוכלך, כי הוא בונה מהדיסק ולא מ-HEAD — אחרת האתר היה
מקבל קוד שלא נמצא בשום קומיט. לעקוף במודע: `npm run deploy -- --allow-dirty`.

`check:size` נכשל אם קובץ שאמור להיכנס ל-precache לא נמצא בו. workbox משמיט
קובץ שחורג מ-4MB **בשקט**, וההתקנה מפסיקה לעבוד אופליין בלי שום שגיאה — לכן
הבדיקה נעשית מול המניפסט שנוצר ב-`dist/sw.js` ולא מול חיקוי של הכללים.
השמטה מכוונת נרשמת ב-`EXPECTED_OUT` שבסקריפט, עם הסיבה.

`.github/workflows/ci.yml` רץ על כל push ל-main ומריץ typecheck, בדיקות ובנייה.
**הוא לא פורס.** ✅ ירוק שם אומר שהקוד תקין, לא שהאתר עודכן.

למה לא דרך Actions: `actions/deploy-pages` חרג דרך קבע מהטיימאאוט שלו על
ארטיפקט של 32MB, ואז ביטל את הפריסה והשאיר את האתר על גרסה ישנה.

`base` הוא `/tavor-gym/` ומוגדר ב-`vite.config.ts`. הניתוב הוא **hash routing** —
כך אין 404 ברענון ואין צורך בטריקים.

## גיבוי

הנתונים קיימים רק במכשיר הזה. הגיבוי הוא רשת הביטחון האמיתית — לא `persist()`.

- **ייצוא נתונים** — קובץ JSON אחד עם הקטלוג, התוכניות, כל האימונים, הסטים, הדירוגים, השיאים ומשקלי הגוף
- **ייצוא סרטונים** — קובץ zip נפרד, כי הוא גדול

מסך הבית מזכיר בעדינות אם עברו 30 יום מהגיבוי האחרון.
